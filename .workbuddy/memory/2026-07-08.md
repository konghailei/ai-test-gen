**现象**：产品「测试2」(PROD-57100-974) 下两需求：

**用户疑问**：第二个需求（V2.0）按理应触发 KB 提问，为什么没提问？是「已不需要」还是「应该提问但没提」？

**结论**：**应该提问但没提（逻辑缺陷），不是「已不需要」**。
- 证据：V2.0 原文档首行明确写「本文档仅描述 V2.0 相对于 V1.0 的新增与优化项。完整上下文请参见 V1 文档」——典型的增量/依赖历史文档，单独看不完整，理应用 KB 检索 V1 补全基础上下文（账号密码登录、密码规则、错误处理等 V1 内容在 V2.0 被刻意略过）。

**根因（两层）**：
1. req_agent 的 LLM 解析把增量文档脑补成完整 SRR，掩盖「V2.0 实际是增量、依赖 V1」这一事实。
2. KB 查询触发面过窄：代码实锤 `_formulate_kb_questions`（clarify_agent.py:382）只遍历 `completeness.critical_missing + important_missing`（字段缺失）。V2.0 字段全齐→空列表→`_query_kb_for_answers` 收到空→只做 check_kb_status→不查 KB→quality_score=1.0→直接 active。

**待确认修复方向**（尚未动手）：
- 方案A（最小改动，直击 V2.0 场景）：clarify 阶段增加「增量/依赖历史检测」——若文档自我声明增量（标题含 V2/V3 或正文含「参见 V1」「增量」「新增与优化」「完整上下文请参见」等），或非产品首个需求且 SRR 明显局部描述，则强制生成一条 KB 查询「该产品的历史需求（如 V1）中登录功能的基础流程/密码规则/错误处理包含哪些？」去 KB 补全基础上下文。

## 修复：KB 查询三个质量问题（陈述句/编造缺口/低质答案）

**问题**（用户查最新 V2.0 KB 查询日志发现）：
1. **陈述句而非问句**：几乎所有查询都是话题短语（如「密码RSA加密传输的前端实现方式」），不是完整疑问句，ChromaDB 语义检索命中率低
2. **幻想编造缺口**：生成了「注册时必填字段」「密码重置入口」「新密码不能与旧密码相同」等登录需求中不存在的主题

**根因**：
- SYSTEM_PROMPT 自身示例就是话题短语（「JWT access_token的有效期和存储方式」——无问号），教坏了 LLM
- 无反编造指令，LLM 根据「登录系统」的通用知识自行扩展主题
- `_query_kb_for_answers` 采纳阈值仅 0.6，低相关度答案被误纳

**修复**（三刀）：

1. **Prompt 改为强制问句格式**：
   - SYSTEM_PROMPT 原则2：「每条查询必须是完整的自然语言问句，以？结尾。话题短语命中率远低于完整问句」

   - user prompt：改为「拆分为多条自然语言问句（每条以？结尾）」+「必须是完整的疑问句」

2. **三层反编造**：
   - SYSTEM_PROMPT 新增原则3：「只查缺口列表中的内容，严禁添加列表之外的任何主题」

## v2.11：KB 检索后增加 LLM 答案质量校验（对标知识问答页）

**用户反馈**：KB 查询没有产生好结果，但知识问答页可以正确回答。要求查询严格围绕需求内容范围。

**根因**：知识问答页用 LLM 读检索文档→分析→作答；clarify_agent 仅机械提取字段值，无 LLM 语义分析。
导致：登录查询匹配到注册文档（相似度0.65），系统直接采纳→答案错误。

**修复**：
- `prompts/clarify_agent.py`：新增 `KB_ANSWER_VERIFIER_SYSTEM_PROMPT`——LLM 审核三条规则：①内容相关性 ②范围约束（登录不采纳注册）③信息充分性。宁可拒绝模糊答案。
- `agents/clarify_agent.py`：新增 `_verify_kb_answers(srr, answers)`——检索后在 return 前调用：
  1. 收集所有有来源答案→batch LLM 调用
  2. LLM 逐条判断相关性+提取具体答案+原因
  3. 相关→替换机械答案；不相关→拒收（answered=False+原因）
  4. LLM 失败→保留原始答案（不降级丢弃）

编译通过。**尚未 build 部署**。

## KB 全未命中时强制升级为人工澄清问题

**现象**：V1.0 需求 KB 查询 22 条全未命中（KB 刚清空），但状态直接 active、0 条澄清问题。

**根因**：`clarify()` 中 `_generate_questions` 判定 SRR 足够完整 → 返回 0 条问题 → status="passed"。

  将 `unresolved_qa` 全部映射为人工澄清问题（含原始问题文本、上下文说明）
- 仅限 KB 全未命中时触发（KB 有部分答案时不强制升级，信任 LLM 判断）

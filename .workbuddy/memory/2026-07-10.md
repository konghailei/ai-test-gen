## 模型下载：BAAI/bge-large-zh-v1.5
- 在 `models/` 目录下新建文件夹，下载了项目唯一本地模型 `BAAI/bge-large-zh-v1.5`（中文嵌入模型，1024 维，~1.3GB）到 `models/bge-large-zh-v1.5/`。
- 下载脚本：`scripts/download_model.py`（huggingface_hub snapshot_download + hf-mirror 镜像）。
- **关键坑**：环境走本地 HTTP 代理（`HTTPS_PROXY=http://127.0.0.1:10808`），`huggingface_hub` 底层 httpx 在代理上建 HTTPS 隧道时 TLS 握手 EOF 失败（`ConnectError: [SSL: UNEXPECTED_EOF_WHILE_READING]`），导致下载卡死；`curl` 走同一代理正常。
- **解决**：用 `curl` 逐文件从 `https://hf-mirror.com/BAAI/bge-large-zh-v1.5/resolve/main/<file>` 下载补齐（pytorch_model.bin 已完成，其余 11 个小文件用 curl 补齐）。已在 `models/README.md` 补充代理环境备注。
- 已更新根 `.gitignore`，排除 `models/*/`（保留 `models/README.md` 文档，避免误提交 1.3GB 权重）。
- 验证：config.json `hidden_size=1024` / `max_position_embeddings=512` / `BertModel`，与 bge-large-zh-v1.5 一致；12 个文件齐全，临时 `.cache` 已清理。
- 使用方式：`backend/.env` 设 `EMBEDDING_MODEL_TYPE=local` + `EMBEDDING_MODEL_NAME` 指向该目录，需安装 `sentence-transformers` + `torch`（项目 requirements 已含）。
- 注意：git bash 下创建 venv / 网络访问被 sandbox 拦截，安装依赖与下载需 `dangerouslyDisableSandbox=true`。

## 隐藏 bug 排查（backend 全量）
- 用 Explore 子代理 thorough 扫描 + 本人逐行复核，产出 `BUG_REPORT_2026-07-10.md`。
- **Critical（已核实）**：
  - C1 `config.py:345` `validate_security()` 用 `os.environ.get("MASTER_KEY")` 而非 `self.MASTER_KEY`；`.env` 配置的 MASTER_KEY 被忽略（pydantic-settings 不回填 os.environ），导致生产启动失败或开发期静默用派生密钥 → 历史加密 API Key 无法解密。
  - C2 `crypto.py:38` `_ENV_KEY = os.environ.get("MASTER_KEY","")` 同源，加密主密钥口径与 config 不一致。
  - 注：docker-compose 经 `env_file` 注入为真实环境变量，故容器内部署不触发；不经 compose 注入的运行方式会触发。
- **High（已核实）**：
  - H1 `vector_store.py`(50-51,139,156) + `main.py:271` 用 `os.getenv` 读 EMBEDDING_MODEL_TYPE/NAME/DEVICE、VECTOR_STORE，`.env` 配置被静默忽略（Docker 内因 compose 显式设环境变量可用）。
  - H2 `auth.py:_decode` 只验签不校验 exp，`api/auth.py` 的 change_password/get_me 直接调它 → 过期 JWT 可改密码/读信息。
  - H3 `milvus_store.py` 全同步方法（含 SentenceTransformer.encode、connections.connect、collection.search 等），被 async 端点直接调用阻塞事件循环；全局连接无锁竞态。代码库无 to_thread/run_in_executor 卸载。
- **Medium（部分已核实）**：M1 milvus `get_all_*` 在 product_id=None 传 expr=""；M2 用户输入直拼 milvus expr（注入）；M3 `quality_gate.py:215` `h.get`/`len` 对非 dict/非字符串抛异常崩溃流水线；另有 M4 SSE commit 时序、M5 限流丢余数、M6 ClarifyAgent 死代码、M7 req_id 碰撞、M8 health 误报。
- 已确认无 SQL 注入、password.py PBKDF2 正确、JWT 核心验签+exp 齐全、database get_session 正确。
- 未修改任何业务代码，仅产出报告。用户未要求修复；已提议可分批修 C1/C2/H1/H2/H3。

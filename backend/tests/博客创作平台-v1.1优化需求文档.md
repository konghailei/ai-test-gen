## A. 编辑器与创作体验优化

### OPT-A-01 图片素材库

**现状问题**: 图片只能随写随传、无法跨文章复用；作者无处集中查看和管理已上传图片；更换或重复插图需重新上传；删除文章后产生大量孤儿图片占用存储配额。

**优化方案**:

- 编辑器新增"图片素材库"面板（侧滑抽屉），按上传时间倒序展示作者全部图片，含缩略图、文件大小、上传时间、被引用文章数
- 支持素材库分组：默认分组 + 用户自建分组（≤ 20 个），图片可拖动归组
- 素材库图片支持点击或拖拽直接插入正文；复用已有图片不重复上传（按文件哈希去重存储）
- 仅未被引用的图片可直接删除；已被引用的图片删除时需二次确认，且仅从素材库列表移除，已发布文章中的展示不受影响
- 素材库顶部展示已用容量/总容量；图片格式与单文件大小沿用现有上传规则，另新增个人总量配额 2GB

**验收标准**:

- [ ] 素材库首屏加载 ≤ 1 秒（500 张以内），滚动分页加载
- [ ] 同一图片（哈希一致）在多篇文章中复用时仅存储一份
- [ ] 删除已引用图片后，相关文章内容渲染不受影响
- [ ] 容量使用达 90% 时界面提醒；达到上限时阻止上传并提示清理
- [ ] 素材库上传支持的图片格式、单文件大小限制及超限提示，与现有图片上传规则完全一致
- [ ] 素材库仅本人可见，不对外暴露

**优先级**: P0

**效果度量**: 图片复用率 ≥ 20%；图片重复上传流量下降 ≥ 30%。

### OPT-A-02 历史版本对比与手动版本标记

**现状问题**: 文章历史版本仅支持直接回滚，回滚前无法预览版本内容，作者不清楚各版本差异，误回滚风险高；自动保存版本刷屏，关键修改节点难以定位。

**优化方案**:

- 版本列表区分"手动标记版本"与"自动保存版本"，展示版本时间、字数变化（+/-）、保存来源
- 支持任选两个版本进行左右分栏差异对比，新增/删除内容高亮显示
- 支持对任意版本"标记"（自定义名称 ≤ 20 字）；手动标记版本独立于自动保存版本的数量上限，自动保存版本仍按现有保留策略执行，手动版最多保留 50 个，超出提示清理
- 回滚前强制展示目标版本与当前版本的差异对比页，二次确认后方可执行

**验收标准**:

- [ ] 任意两版本差异对比渲染 ≤ 2 秒（20 万字以内文章）
- [ ] 回滚操作路径中必须经过差异对比页，无法跳过
- [ ] 手动标记版本的删除需二次确认；回滚产生的新版本自动标记"回滚自 xx 版本"
- [ ] 手动标记版本长期保留，不设数量上限
- [ ] 版本数据仅作者本人可见

**优先级**: P1

**效果度量**: 误回滚相关反馈归零；版本功能周活跃使用作者占比 ≥ 15%。

### OPT-A-03 发布前检查与预览模式

**现状问题**: 文章发布后常发现坏图、失效链接、漏选标签等问题，需要再次编辑修正；已发布文章的二次编辑会产生重复通知，打扰关注者。

**优化方案**:

- 点击"发布"后自动执行发布前检查并输出检查单：
  - 错误项（必须修复后才能发布）：标题不合规、分类或标签不符合发布要求、正文存在加载失败的图片
  - 警告项（可忽略并强制发布）：未设置摘要、未设置封面、正文含无法访问的外链、字数 < 100
- 新增"预览"按钮：以文章详情页完整样式渲染当前内容（含目录、代码高亮、移动端效果切换），预览不产生任何公开数据
- 已发布文章的"小修订"（正文改动 < 5%）不向关注者发送更新通知，仅调整通知触发条件，通知体系本身不变

**验收标准**:

- [ ] 发布前检查在 3 秒内完成并展示结果；错误项未清零时发布按钮置灰
- [ ] 预览模式与正式详情页渲染一致性 ≥ 99%（同一内容无样式差异）
- [ ] 预览页面不可被搜索引擎收录、不可被未授权访问（临时令牌，1 小时有效）
- [ ] 小修订不触发关注通知的判定准确率可通过埋点验证（误判率 < 1%）

**优先级**: P0

**效果度量**: 发布后 1 小时内再次编辑的文章占比下降 ≥ 50%；发布完成率（点击发布 → 成功发布）≥ 92%。

### OPT-A-04 "/" 命令菜单与文本片段

**现状问题**: 插入表格、代码块等结构需多次点击工具栏，手不离键的写作流被打断；常用内容结构（文章头部模板、参考链接区块等）重复手工输入。

**优化方案**:

- 空行行首输入"/"唤起命令菜单：标题（H2~H4）、代码块（可选语言）、表格（预设 2×3 / 3×3 / 自定义行列）、公式、引用、任务列表、图片、分割线；支持键盘上下选择、回车确认、模糊搜索过滤
- 文本片段（Snippet）：系统预置 + 用户自定义（≤ 50 条；名称 ≤ 20 字，内容 ≤ 2000 字），通过"/"菜单或自定义快捷键插入；支持变量占位符 {{date}}（当日日期）、{{author}}（作者昵称）
- 命令菜单与工具栏并存，现有工具栏保留不变（向下兼容）

**验收标准**:

- [ ] "/"菜单唤起响应 ≤ 100ms，菜单项过滤检索 ≤ 50ms
- [ ] 自定义片段支持新建、编辑、删除、排序（拖拽），操作即时生效
- [ ] 变量占位符在插入时替换为实际值，且不再随时间变化
- [ ] 命令菜单在移动端隐藏（仅桌面端启用），不影响移动端原有输入

**优先级**: P1

**效果度量**: 启用该功能的作者平均单篇编辑耗时下降 ≥ 10%（对照灰度组）。

### OPT-A-05 专注模式与打字机模式

**现状问题**: 编辑页界面元素较多（导航、预览栏、工具栏），长文写作易分心；长文写作时光标常贴近屏幕底部，视线疲劳。

**优化方案**:

- 专注模式：一键隐藏顶部导航与侧边元素，仅保留编辑器与极简悬浮工具条；Esc 或再次点击退出；快捷键 F8（可自定义）
- 打字机模式：光标所在行始终保持在视口约 1/2 位置，其余段落降低不透明度（可在设置中开关，默认关闭）
- 两种模式的开关状态按用户偏好持久化（账户级设置）

**验收标准**:

- [ ] 专注模式进入/退出无页面刷新，切换耗时 ≤ 100ms
- [ ] 专注模式下自动保存、草稿能力不受影响
- [ ] 打字机模式开启后滚动性能无明显劣化（帧率 ≥ 50fps）
- [ ] 用户设置项可在"个人中心 → 编辑器偏好"中修改并即时生效

**优先级**: P2

**效果度量**: 专注模式周使用作者占比 ≥ 10%。

### OPT-A-06 草稿箱文件夹与清理提醒

**现状问题**: 草稿数量增多后检索困难；长期废弃草稿无提醒机制，占用配额。

**优化方案**:

- 草稿箱支持文件夹（≤ 10 个，含不可删除的"默认文件夹"），草稿可拖拽归组，支持按文件夹筛选
- 超过 180 天未编辑的草稿标注"长期未编辑"角标，列表顶部提供一键清理入口（批量勾选删除，删除需二次确认）
- 草稿列表新增按标题关键词过滤的筛选框

**验收标准**:

- [ ] 文件夹增删改操作 ≤ 500ms 生效；删除非空文件夹时其草稿自动归入默认文件夹并提示
- [ ] "长期未编辑"判定以最后编辑时间为准，每日更新一次
- [ ] 清理操作全程不自动删除任何草稿，必须用户逐项/批量确认

**优先级**: P2

**效果度量**: 草稿箱平均空闲配额提升；找到目标草稿的平均操作数下降。

### OPT-A-07 多端编辑冲突处理

**现状问题**: 草稿支持多端同步，但未定义并发编辑的冲突行为；同一账号在两台设备同时编辑同一草稿时，后保存方会静默覆盖先保存方内容，存在丢稿风险。

**优化方案**:

- 采用版本号乐观锁：草稿每次保存版本号 +1；保存时若本地版本落后于服务端最新版本，阻止直接覆盖
- 冲突时弹出冲突处理弹窗：展示"服务端最新版本"与"本机版本"的内容摘要与差异对比，提供三个选项——保留服务端版本、用本机版本覆盖、两者都保留（本机内容另存为新草稿，标题追加"-本机备份"）
- 打开草稿时若检测到同账号其他设备正在编辑该草稿，顶部展示非阻断提示条

**验收标准**:

- [ ] 并发编辑场景下任何一次保存都不会静默丢失内容（可通过自动化并发用例验证）
- [ ] 冲突弹窗中差异对比渲染正确，三个选项均可正常执行并可撤销（另存草稿路径）
- [ ] 弱网环境（断网 10 秒内恢复）下本地编辑内容不丢失，恢复后按冲突流程处理
- [ ] 同设备多标签页编辑同一草稿同样适用该冲突机制

**优先级**: P1

**效果度量**: 丢稿类用户反馈归零。

### OPT-A-08 写作状态栏与大纲面板

**现状问题**: 编辑过程中仅有总字数信息，作者缺乏对文章结构与阅读体量的感知。

**优化方案**:

- 编辑器底部状态栏实时展示：字数、图片数、代码块数、预计阅读时长（按 400 字/分钟计算）
- 编辑侧新增大纲面板：基于标题层级实时生成，点击跳转至对应位置，随编辑实时更新

**验收标准**:

- [ ] 状态栏数据更新延迟 ≤ 500ms，输入过程不卡顿
- [ ] 大纲与正文标题层级实时一致；无标题时展示空态引导
- [ ] 阅读时长仅用于编辑期展示，不新增详情页展示内容

**优先级**: P2

**效果度量**: 长文（≥ 3000 字）完稿率提升 ≥ 5%。

## B. 最小内容安全方案

> 本节用于解决平台当前"无内容审核"带来的合规风险（垃圾广告、违规内容可直接上线）。本期**不建设完整管理后台**，仅提供"机器过滤 + 用户举报 + 轻量内部处置入口"的最小能力。

### OPT-B-01 敏感词过滤

**现状问题**: 文章、评论、个人资料的发布链路无任何内容校验，违规内容与广告可直接上线，存在合规与社区氛围风险。

**优化方案**:

- 检测范围：文章发布与编辑、评论与回复提交、昵称/个人简介修改、专栏名称与简介
- 词库分级处置：
  - 拦截级：命中即阻止提交，提示"内容包含违规信息，请修改后重试"（不告知具体命中词）
  - 替换级：允许提交，命中内容自动以 * 号替换展示
- 词库维护：存储于配置中心/数据库，通过脚本或内部接口热更新（无需管理界面），更新操作记录审计日志；变更 5 分钟内全网生效
- 匹配预处理：全角转半角、去除常见干扰符号、大小写归一后再匹配，降低变体绕过
- 所有拦截事件落日志：用户 ID、时间、场景、命中词、上下文片段（脱敏存储）

**验收标准**:

- [ ] 单篇 20 万字文章的匹配耗时 ≤ 200ms，不阻塞发布体验（异步超时 2 秒则放行并记录）
- [ ] 词库热更新 5 分钟内生效，更新过程不影响在线服务
- [ ] 拦截与替换日志完整可查，日志保留 ≥ 1 年
- [ ] 提供误拦截申诉通道：复用 OPT-B-02 举报入口反向提交，人工复核后可恢复内容

**优先级**: P0

**效果度量**: 违规内容曝光前拦截率 ≥ 95%；误拦截申诉率 ≤ 1%。

### OPT-B-02 用户举报与处置流程

**现状问题**: 用户发现不良内容无任何反馈渠道；运营侧无数据可依，问题内容只能靠用户吐槽被动发现。

**优化方案**:

- 举报入口：文章详情页、评论、个人主页均提供"举报"按钮
- 举报表单：原因单选（垃圾广告 / 违法违规 / 抄袭侵权 / 辱骂骚扰 / 其他）+ 补充描述（≤ 200 字，可选）；举报人身份对被举报人不可见；同一用户对同一目标的重复举报自动合并
- 轻量内部处置入口（非完整管理后台）：仅限内网/白名单 IP 访问的举报查询与处置页面，支持查看举报详情与上下文，执行处置动作：内容下架、对账号禁言（1/7/30 天）、封禁账号、驳回举报；全部操作记录审计日志
- 处置结果通知：举报成立时通过平台现有通知渠道告知举报人处理结果（不透露对被举报人的具体处罚）；被处置用户收到违规通知与违规条款引用
- 处置时效要求：举报处理 P50 ≤ 24 小时，P95 ≤ 72 小时

**验收标准**:

- [ ] 三类入口（文章/评论/主页）均可完成举报提交，提交成功率 ≥ 99.9%
- [ ] 处置页面具备访问白名单与操作审计，审计日志不可篡改、保留 ≥ 2 年
- [ ] 被下架内容在处置后 ≤ 1 分钟内全站不可见（含搜索索引与 RSS）
- [ ] 申诉期内被处置用户可提交一次申诉，申诉由不同处理人复核

**优先级**: P0

**效果度量**: 举报处理时效达标率 ≥ 95%；被 3 人以上举报的内容仍在线超 24 小时的比例 ≤ 2%。

### OPT-B-03 新账号风控（防垃圾灌水）

**现状问题**: 批量注册的机器人账号可在无任何门槛的情况下发文刷评论，投递广告链接。

**优化方案**:

- 新账号（注册 < 24 小时或邮箱未完成验证）限制：单篇外链 ≤ 2 个、评论频率在现有限制基础上收紧为间隔 ≥ 30 秒、单日发文 ≤ 3 篇
- 注册与登录增加行为风控：同一 IP 单日注册 ≥ 3 个账号时，后续注册强制图形验证码；同一 IP 高频登录失败触发验证码升级
- 命中拦截级敏感词库的账号自动标记"高危"，连续命中 3 次自动禁言 24 小时并进入处置队列人工复核
- 所有风控规则参数化配置，可热调整

**验收标准**:

- [ ] 新账号限制规则全部可配置且默认值生效，超限操作被阻止并给出友好提示
- [ ] 图形验证码接入后，同 IP 批量注册成功率下降 ≥ 80%（压测/演练验证）
- [ ] 风控误伤普通用户的申诉通道复用 OPT-B-02 流程
- [ ] 风控规则变更具备审计日志

**优先级**: P1

**效果度量**: 垃圾内容举报量占比下降 ≥ 60%；新注册账号中疑似机器账号占比 ≤ 3%。

## 数据埋点与效果验证

本次优化点需配套以下埋点，作为上线后效果复盘依据：

- 功能埋点：每个 OPT 项的入口曝光量、点击/使用率、完成率（如发布前检查的修复完成率、素材库复用次数、命令菜单调用次数）
- 核心观察指标：发布完成率、发布后 1 小时内二次编辑率、作者 7 日留存、平均单篇编辑耗时、丢稿反馈数、举报处理时效
- 灰度策略：OPT-A 类优化先对 20% 作者灰度 2 周，核心指标（发布完成率、编辑耗时）无劣化后全量；OPT-B 类安全能力不做灰度，直接全量上线
- 复盘节点：全量上线后第 2 周与第 8 周各一次数据复盘，未达标优化点进入下一迭代

## 依赖与风险

**依赖**：敏感词初始词库需法务参与构建并定期复审；举报处置内部页面需运维配置内网白名单与审计日志采集；版本对比与素材库涉及存储结构扩展，需数据库迁移评审；风控验证码服务需选型接入。

**风险**：敏感词误拦截技术类正常内容（如安全攻防类文章），通过白名单词条 + 申诉通道缓解；内部处置页面虽非完整后台，仍属管理面暴露，必须强制审计与最小权限；灰度期间新旧编辑器状态并存，需保证草稿数据双向兼容。

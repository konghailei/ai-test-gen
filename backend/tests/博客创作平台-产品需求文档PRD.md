# 产品需求文档（PRD）：DevBlog 技术博客创作平台

**版本**: 1.0
**日期**: 2026-08-04
**作者**: Sarah（Product Owner）
**质量评分**: 90/100
**交付方式**: 一次性全量交付（按优先级标注 P0/P1/P2）

---

## 执行摘要

DevBlog 是一个面向技术开发者的多用户博客创作平台，定位类似掘金、博客园。任何开发者都可以注册成为作者，使用 Markdown 编辑器发布技术文章；读者可以浏览、搜索、评论、点赞、收藏并关注感兴趣的作者与标签。

当前开发者分享技术内容主要依赖少数头部平台，存在内容同质化、个人品牌沉淀弱、技术写作体验（代码高亮、公式、目录）参差不齐等问题。DevBlog 以"极致的技术写作体验 + 活跃的技术内容生态"为核心切入点，为开发者提供一个专注、纯粹、功能完整的技术内容社区。

平台成功的核心衡量标准是内容生态的健康度：注册作者数、发文量、日活/月活及互动率。本文档覆盖账户与用户体系、内容创作与管理、社区互动、搜索与通知、数据统计等全部功能域，采用 Web 响应式形态，一次性全量交付。

---

## 问题陈述

**现状与痛点**:
技术开发者撰写与获取技术内容时面临以下问题：一是通用博客平台对技术写作支持不足，代码高亮、数学公式、目录导航等能力缺失或体验差；二是头部内容社区流量分配集中，新作者难以获得曝光，个人品牌难以沉淀；三是读者在海量内容中难以高效找到高质量技术文章，搜索与筛选能力薄弱。

**解决方案**:
构建一个专注技术领域的多用户博客平台：为作者提供专业级 Markdown 编辑器（代码高亮、公式、图片上传、草稿箱），为读者提供结构化内容组织（分类、标签、专栏）与精准全文搜索，并通过评论、点赞、收藏、关注、消息通知构建完整的社区互动闭环。

**业务影响**:
上线 6 个月内目标：注册用户 ≥ 50,000，月活跃作者 ≥ 3,000，累计文章 ≥ 20,000 篇，次日留存 ≥ 30%。

## 成功指标

**核心 KPI（内容生态指标）:**

| 指标 | 目标值（上线 6 个月） | 统计方式 |
|------|----------------------|----------|
| 注册用户数 | ≥ 50,000 | 用户表累计注册数 |
| 月活跃作者数 | ≥ 3,000 | 当月发布/编辑过文章的独立用户数 |
| 累计文章数 | ≥ 20,000 篇 | 已发布文章总数（不含草稿、已删除） |
| DAU / MAU | DAU ≥ 8,000，MAU ≥ 25,000 | 埋点统计日/月独立访问用户 |
| 互动率 | ≥ 15% | 产生评论/点赞/收藏/关注行为的用户占比 |
| 作者次月留存 | ≥ 40% | 本月发文作者中下月仍发文或登录的比例 |

**验证方式**: 通过埋点数据平台每日更新指标看板，上线后第 1、3、6 个月进行三次复盘；上线前进行 Beta 内测（邀请 200 名种子用户），验证核心发布与阅读流程的完成率 ≥ 95%。

## 用户画像

### 主要画像：技术作者（小张，后端工程师，3 年经验）

- **角色**: 有分享欲的开发者，希望通过写文章沉淀知识、建立个人影响力
- **目标**: 顺畅地撰写并发布技术文章；获得阅读、点赞、关注等正反馈；积累个人作品集
- **痛点**: 现有平台编辑器对代码块/公式支持差；新作者文章无人问津；写作中途被打断后内容丢失
- **技术水平**: 高级（熟悉 Markdown、Git、主流编程语言）

### 次要画像：技术读者（小李，应届前端开发）

- **角色**: 以学习、查资料为主要目的的开发者
- **目标**: 快速找到高质量技术文章；系统学习某个技术方向；与作者交流疑问
- **痛点**: 搜索结果噪音大；内容质量参差不齐；无法持续跟踪喜欢的作者更新
- **技术水平**: 中级

### 次要画像：技术管理者/面试官（老王）

- **角色**: 浏览平台了解技术趋势、考察候选人的资深从业者
- **目标**: 按主题浏览深度内容；评估作者的技术水平
- **痛点**: 缺少按主题聚合的深度内容入口
- **技术水平**: 高级

## 用户故事与验收标准

### 故事 1：作者发布文章

**作为** 技术作者
**我想要** 使用 Markdown 编辑器撰写并发布文章，设置分类、标签和封面
**以便** 把我的技术知识分享给社区

**验收标准:**

- [ ] 编辑器支持标准 Markdown 语法，代码块支持 ≥ 30 种语言高亮，支持数学公式（KaTeX）渲染
- [ ] 支持本地图片上传（单张 ≤ 10MB，支持 png/jpg/gif/webp），上传后自动插入图片链接
- [ ] 发布时必须填写标题（5~120 字），摘要和封面可选；至少选择 1 个分类、1~5 个标签
- [ ] 发布成功后跳转至文章详情页，文章在首页最新列表 1 分钟内可见
- [ ] 内容未保存时离开页面给出二次确认提示；编辑器每 30 秒自动保存草稿

### 故事 2：作者管理草稿

**作为** 技术作者
**我想要** 把未写完的文章保存为草稿，随时继续编辑或删除
**以便** 分多次完成长文创作而不丢失内容

**验收标准:**

- [ ] 草稿箱列表展示标题、最后编辑时间、字数，按编辑时间倒序
- [ ] 草稿可继续编辑、发布或删除；删除需二次确认
- [ ] 草稿内容仅本人可见，不出现在任何公开列表和搜索结果中
- [ ] 单个账号草稿上限 100 篇，超出时提示并阻止新建

### 故事 3：读者浏览与阅读文章

**作为** 技术读者
**我想要** 在首页和分类/标签页浏览文章，并获得舒适的阅读体验
**以便** 高效获取技术知识

**验收标准:**

- [ ] 首页 Feed 支持"最新 / 热门 / 关注"三个 Tab；热门按近 7 天综合热度排序
- [ ] 文章详情页正确渲染 Markdown，包含代码高亮、公式、图片懒加载
- [ ] ≥ 800 字的文章自动生成右侧目录（基于标题层级），滚动时高亮当前章节
- [ ] 移动端自动切换为单栏布局，目录收纳为悬浮按钮

### 故事 4：读者互动（评论/点赞/收藏）

**作为** 技术读者
**我想要** 对文章点赞、收藏并发表评论（支持回复与 Markdown）
**以便** 表达认可、留存优质内容并与作者交流

**验收标准:**

- [ ] 未登录用户点击点赞/收藏/评论时引导登录，登录后回到原页面原位置
- [ ] 评论支持两级嵌套（一级评论 + 回复），支持 Markdown 基础语法与 @提及
- [ ] 每用户对同一文章点赞/收藏为互斥开关（可取消），操作需即时反馈（≤ 200ms 乐观更新）
- [ ] 评论者可删除自己的评论；作者可删除自己文章下的任意评论
- [ ] 空内容、纯空白评论不可提交；单条评论 ≤ 2000 字

### 故事 5：用户关注与订阅

**作为** 技术读者
**我想要** 关注喜欢的作者和标签，在"关注"Tab 查看其最新内容
**以便** 持续跟踪感兴趣的技术方向

**验收标准:**

- [ ] 在作者主页、文章详情页可关注/取消关注作者；在标签页可关注标签
- [ ] "关注"Feed 聚合所关注作者的新文章与所关注标签下的热门文章
- [ ] 关注后 10 秒内，被关注者发布的新文章出现在关注 Feed 中
- [ ] 个人主页展示"关注数 / 粉丝数 / 获赞总数"

### 故事 6：全文搜索

**作为** 技术读者
**我想要** 按关键词搜索文章并按维度筛选
**以便** 快速找到目标技术内容

**验收标准:**

- [ ] 搜索范围覆盖标题、正文、标签、作者名；输入 ≥ 2 字符触发，响应 ≤ 500ms
- [ ] 结果支持按相关度/最新发布排序，支持按分类、标签、发布时间筛选
- [ ] 搜索词高亮显示；空结果时推荐热门分类与热门搜索词
- [ ] 未登录用户可搜索；搜索关键词记录用于生成热门搜索榜

### 故事 7：消息通知

**作为** 平台用户
**我想要** 收到评论、回复、点赞、收藏、关注及系统通知
**以便** 及时获知与我相关的互动动态

**验收标准:**

- [ ] 通知类型包括：收到评论、收到回复、被点赞、被收藏、被关注、系统公告
- [ ] 导航栏铃铛显示未读数（>99 显示 99+），点击展开通知列表，支持全部已读与按类型筛选
- [ ] 站内通知实时送达（≤ 5 秒）；用户可在设置中关闭某类通知
- [ ] 通知聚合：同一文章 1 小时内被多人点赞聚合为一条（显示最近 3 位用户）

### 故事 8：注册登录与个人中心

**作为** 访客
**我想要** 通过邮箱或第三方账号快速注册登录，并管理我的资料
**以便** 开始创作或参与互动

**验收标准:**

- [ ] 支持邮箱 + 密码注册（密码 ≥ 8 位，含字母和数字，邮箱验证码校验）与邮箱验证码登录
- [ ] 支持第三方登录：GitHub、Google、微信（首次第三方登录需绑定邮箱）
- [ ] 连续输错密码 5 次锁定账号 15 分钟；登录态有效期 30 天，支持"记住我"
- [ ] 个人中心支持修改昵称（唯一，2~20 字）、头像（≤ 5MB）、个人简介（≤ 200 字）、个人主页链接
- [ ] 设置页支持修改密码、绑定/解绑第三方账号、注销账号（注销需二次确认并保留 7 天冷静期）

### 故事 9：作者数据统计

**作为** 技术作者
**我想要** 查看我的文章浏览量、互动数据与粉丝变化
**以便** 了解内容表现并调整写作方向

**验收标准:**

- [ ] 作者数据看板展示：总浏览、总点赞、总收藏、总评论、粉丝数及近 30 天趋势图
- [ ] 单篇文章维度展示浏览、点赞、收藏、评论数，支持按时间排序导出（CSV）
- [ ] 数据更新延迟 ≤ 1 小时

### 故事 10：RSS 订阅

**作为** 技术读者
**我想要** 通过 RSS 阅读器订阅作者或全站最新文章
**以便** 在我习惯的工具中持续获取内容

**验收标准:**

- [ ] 提供全站最新文章 RSS 与按作者的 RSS，地址形如 `/rss/latest.xml`、`/rss/user/{username}.xml`
- [ ] RSS 输出符合 RSS 2.0 规范，包含标题、摘要（前 300 字）、链接、发布时间
- [ ] 新文章发布后 ≤ 10 分钟在 RSS 中可见

## 功能需求

### 模块一：账户与用户体系（P0）

**1.1 注册与登录**
- 功能描述：邮箱 + 密码注册（邮箱验证码激活）、邮箱验证码登录、密码登录；第三方 OAuth 登录（GitHub / Google / 微信）。
- 用户流程：访客点击注册 → 填写邮箱/密码 → 收取验证码 → 激活成功自动登录 → 引导完善资料。
- 边界情况：邮箱已注册提示并引导找回密码；验证码 10 分钟有效、60 秒内不可重发；第三方账号已绑定其他平台邮箱时提示冲突处理。
- 错误处理：登录失败给出明确原因（密码错误/账号不存在/已锁定）；验证码错误 ≥ 5 次当日作废重发。

**1.2 个人资料与个人主页**
- 功能描述：昵称、头像、简介、职位、公司、个人网站；个人主页展示文章列表、专栏、关注/粉丝数、获赞总数。
- 用户流程：个人中心编辑 → 保存即时生效；个人主页支持访客查看与关注。
- 边界情况：昵称全局唯一且仅允许中英文、数字、下划线；头像格式限 png/jpg/webp。
- 错误处理：上传失败保留原头像并提示原因；昵称被占用实时提示可用建议。

**1.3 权限模型**
- 功能描述：角色分为游客（只读浏览/搜索）、注册用户（互动）、作者（注册即具备，发布文章后激活创作者身份）。本期不含管理员角色。
- 边界情况：未登录访问写作页重定向至登录页；注销账号后内容匿名化处理（文章保留、作者显示"已注销用户"）。

### 模块二：内容创作与管理（P0）

**2.1 Markdown 编辑器**
- 功能描述：分屏实时预览的 Markdown 编辑器；代码块语言高亮（≥30 种语言）、KaTeX 数学公式、表格、任务列表、引用、脚注；本地图片上传与粘贴上传；快捷键（加粗/标题/代码块/图片）；工具栏一键插入。
- 用户流程：新建文章 → 编辑（自动保存草稿，30 秒间隔）→ 填写发布设置（分类/标签/封面/摘要）→ 发布。
- 边界情况：单篇文章正文 ≤ 200,000 字；粘贴图片自动上传；网络中断时本地缓存不丢稿，恢复后自动同步。
- 错误处理：图片上传失败标记重试；保存失败在编辑器顶部持续提示直至成功。

**2.2 文章管理**
- 功能描述：文章的发布、编辑、删除、撤回（转回草稿）；分类（平台预置，如前端/后端/AI/DevOps/架构，单选）与标签（用户自定义 + 平台已有标签，1~5 个）；封面图与摘要；已发布文章编辑后保留历史版本（最近 20 版，作者可回滚）。
- 边界情况：删除文章需二次确认，删除后 30 天内可在回收站恢复，之后物理清除；标签重名自动归一。
- 错误处理：历史版本回滚失败保留当前版本并告警。

**2.3 草稿箱**
- 功能描述：草稿列表、继续编辑、发布、删除；自动保存与手动保存；多端草稿同步。
- 边界情况：上限 100 篇；草稿不计入任何公开统计。

**2.4 专栏（合集）**
- 功能描述：作者可创建专栏，将系列文章归集排序（如"Redis 源码解析"）；专栏含名称、简介、封面；读者可收藏专栏。
- 边界情况：单专栏文章 ≤ 100 篇；同一文章可属于多个专栏。

### 模块三：内容展示与阅读（P0）

**3.1 首页 Feed**
- 功能描述：最新 / 热门 / 关注三 Tab；文章卡片含标题、摘要、作者、分类、浏览/点赞/评论数；无限滚动分页（每页 20 条）。
- 热门算法（初版）：热度分 = 浏览×1 + 点赞×5 + 评论×8 + 收藏×6，按近 7 天衰减加权。

**3.2 文章详情页**
- 功能描述：正文渲染（代码高亮/公式/图片懒加载）、右侧目录（≥800 字自动生成）、阅读进度条、作者卡片（关注入口）、上一篇/下一篇（同专栏内）、互动栏（点赞/收藏/评论/分享/复制链接）、版权说明（默认"署名-非商业使用"）。
- 边界情况：超长代码块横向滚动不换行；图片加载失败显示占位图与重试。

**3.3 分类页与标签页**
- 功能描述：按分类/标签聚合文章，支持按最新/热门排序；标签页显示关注人数与文章数。

**3.4 SEO 优化**
- 功能描述：文章页服务端渲染（SSR/SSG），语义化标签、sitemap.xml、结构化数据（Article Schema）、自定义 TDK；未登录可完整阅读文章。

### 模块四：社区互动（P0）

**4.1 评论系统**
- 功能描述：两级嵌套评论、Markdown 支持、@提及、评论点赞、删除（本人评论/作者删自己文章下评论）、按时间正序展示。
- 边界情况：评论频率限制（同一用户 10 秒内限 1 条，1 小时限 30 条）；被 @用户收到通知。

**4.2 点赞与收藏**
- 功能描述：文章点赞/取消点赞；收藏至个人收藏夹（默认收藏夹 + 自建收藏夹，收藏夹可私密/公开）。
- 边界情况：收藏夹 ≤ 50 个，单收藏夹文章 ≤ 1000 篇。

**4.3 关注体系**
- 功能描述：关注作者、关注标签；关注列表与粉丝列表；关注 Feed。
- 边界情况：单用户关注上限 2000；不允许重复关注；取关静默处理不通知对方。

### 模块五：搜索（P0）

- 功能描述：全文搜索（标题/正文/标签/作者），搜索建议（输入联想，≤ 300ms），结果按相关度/最新排序，筛选器（分类/标签/时间范围），热门搜索榜（每小时更新），历史搜索记录（仅本人可见，可清空）。
- 边界情况：搜索词 ≤ 100 字符并做转义防注入；无结果给出推荐；高频搜索做缓存（1 分钟）。

### 模块六：消息通知（P1）

- 功能描述：互动通知（评论/回复/点赞/收藏/关注/@）、系统通知（公告、文章被推荐）；站内实时通知（WebSocket）+ 可选邮件通知；未读角标；通知聚合与按类型筛选；通知偏好设置。
- 边界情况：自己对自己的行为不产生通知；通知保留最近 1 年。

### 模块七：数据统计（P1）

- 功能描述：作者数据看板（总览 + 30 天趋势图 + 单篇明细 + CSV 导出）；文章浏览去重统计（同 IP 同用户 30 分钟内计 1 次）。
- 边界情况：数据延迟 ≤ 1 小时；导出单次上限 10,000 行。

### 模块八：RSS 订阅（P2）

- 功能描述：全站最新 RSS、按作者 RSS、按标签 RSS；RSS 2.0 标准输出；每条含标题/摘要/链接/时间。

### 范围外（本期不做）

以下内容明确不在本期范围内：管理后台与内容审核系统（经需求方确认暂不包含）、付费阅读/会员/广告等商业化功能、移动 App 与小程序、私信/聊天、AI 辅助写作与 AI 推荐算法、多语言国际化（仅简体中文）、开放 API。

> 风险提示：多用户平台缺少内容审核存在合规风险（垃圾广告、违规内容），建议至少预留"用户举报 + 人工处理入口"的最小方案，详见风险评估。

## 技术约束

### 性能要求

- 页面首屏加载 ≤ 2 秒（4G 网络、中端设备）；文章详情页 LCP ≤ 2.5 秒
- 核心 API P95 响应 ≤ 300ms；搜索 P95 ≤ 500ms
- 支撑目标：10,000 并发在线用户、日 PV 100 万；接口限流与降级预案
- 图片经 CDN 分发并自动压缩/WebP 转换；静态资源缓存命中率 ≥ 95%

### 安全要求

- 密码使用 bcrypt/argon2 加盐哈希存储，禁止明文与可逆加密
- 登录态使用 HttpOnly + Secure Cookie（或 JWT + 刷新令牌机制），防 XSS（输出转义、CSP）与 CSRF（Token 校验）
- Markdown 渲染前进行 HTML 消毒（白名单过滤），防止存储型 XSS
- 关键接口（注册、登录、验证码、评论）频率限制与风控；敏感操作记录审计日志
- 用户数据遵循最小收集原则；支持账号注销与数据删除（7 天冷静期后清除）
- 全站 HTTPS；依赖项定期安全扫描

### 兼容性

- 浏览器：Chrome / Edge / Firefox / Safari 最近两个大版本
- 响应式断点：桌面 ≥ 1024px、平板 768~1023px、手机 < 768px
- 键盘可达性：发布、阅读、评论核心流程可纯键盘操作

### 建议技术栈（供研发参考，可调整）

- 前端：Next.js（SSR/SSG 满足 SEO）+ TypeScript；编辑器基于成熟 Markdown 方案二次封装
- 后端：Node.js（NestJS）或 Go；RESTful API
- 数据：PostgreSQL（主数据）、Redis（缓存/计数/会话）、Elasticsearch 或 Meilisearch（全文搜索）、对象存储（图片/附件）+ CDN
- 实时：WebSocket（通知推送）

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|----------|

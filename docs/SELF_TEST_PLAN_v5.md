## 1. 本轮目标

用 **AI-Test-Gen 系统自身的需求文档**（三轮）喂给系统，走完整流程生成测试用例；
再用生成好的用例**反过来执行验证系统自身功能**，形成闭环自证。

核心验证点：
1. **需求分析正确性** —— 生成的 SRR/FP 是否准确覆盖系统真实功能
2. **多用户并发上传** —— 并发场景是否稳定
3. **依赖图谱生成正确性** —— 影响分析图谱是否准确
4. **知识问答正确性** —— 能否正确回答并标注来源
5. **知识库纠正** —— 纠正能否正确回写生效
6. **生成的用例可执行性** —— 这是第四轮的核心，检验生成质量

## 2. 四轮结构

### 第一轮：核心全流程基线（v1.0_core_baseline.md）

| 阶段 | 操作 | 目的 |
|------|------|------|
| 1 | 创建产品「AI-Test-Gen 自证」+ 项目「v1.0 核心基线」 | 建立容器 |
| 2 | 上传 v1.0 需求 → 解析 | 验证 SRR/FP 提取完整性 |
| 3 | 澄清（模型严谨答案，禁用 default_answer） | 验证一轮收敛 |
| 4 | FP 分配模块 → 审核 → 确认 | 验证状态流转 |
| 5 | 影响分析 | 验证依赖图谱 |
| 6 | 生成用例 | 验证类型覆盖与质量 |
| 7 | 归档 + 向量化 | 知识入库 |
| 8 | KB 固定查询集（3 问） | 验证问答正确性 |

**固定 KB 查询集**（针对本系统需求）：
1. 「需求上传支持哪些文件格式？单文件大小限制多少？」（关键值：md/docx/txt、10MB）
2. 「登录连续失败几次锁定？锁定多久？」（关键值：5 次、30 分钟）
3. 「澄清问题重复率上限是多少？」（关键值：10%）

### 第二轮：协作与治理增强（v2.0_enhancement.md）

| 阶段 | 操作 | 目的 |
|------|------|------|
| 1 | 项目「v2.0 增强」 | 同产品第二项目 |
| 2 | 上传 v2.0 需求 → 解析 → 澄清 → 确认 | **重点：验证 KB 累积**（第二轮引用的规则应命中第一轮） |
| 3 | 生成用例 → 归档 | KB 累积 |
| 4 | 多用户并发上传测试 | 3 用户并发 |

**KB 累积验证**：第二轮需求中引用了第一轮已归档的规则（如"重复率低于 10%"），
提问时应能命中第一轮归档内容，命中率高于第一轮首次。

### 第三轮：稳定性与边界治理（v3.0_governance.md）

| 阶段 | 操作 | 目的 |
|------|------|------|
| 1 | 项目「v3.0 治理」 | 同产品第三项目 |
| 2 | 上传 v3.0 需求 → 解析 → 澄清 → 确认 | 验证细粒度功能点提取 |
| 3 | 生成用例 → 归档 | 覆盖小功能点 |
| 4 | 回归核验 | 降级路径留痕 |

**重点**：v3.0 集中了大量"小功能点"（看门狗、出箱、脱敏开关、幂等性等），
验证系统能否把这些描述密度低的点也提取为用例。

### 第四轮：用例可执行性验证（核心）

> **本轮不上传需求**，而是用前三轮生成的用例来执行验证系统。

| 步骤 | 操作 | 期望 |
|------|------|------|
| 1 | 汇总前三轮全部用例（按需求/类型/优先级分组） | 完整清单 |
| 2 | 抽取可执行子集（排除破坏性操作类，如"模拟 Milvus 宕机"） | 可执行清单 |
| 3 | API 类用例脚本直调；UI 类用例 Playwright | 逐条执行 |
| 4 | 记录结果矩阵：通过 / 失败 / 不可执行 | 量化 |
| 5 | 双向归因 | 用例缺陷 vs 系统缺陷 |

**双向归因规则**：
- 用例**不可执行**（引用不存在的接口/UI/无触发路径）→ 用例缺陷 → 记入"生成器可执行性"问题
- 用例**可执行但系统行为不符预期** → 系统缺陷 → 记入系统 Bug 清单

## 3. 执行纪律（承接 v4.5）

### 3.1 澄清回答（强制）
- 由**模型生成**严谨答案：含具体数值 + 判定规则 + 边界行为
- **禁用**系统 `default_answer`（伪答案）
- **禁用**脚本硬编码/泛化兜底

### 3.2 隐性前置（见 v4.5 §D）
- FP 必须先分配模块才能审核（否则 409）
- 需求文档须自带非功能需求章节（本轮三轮文档已含 §4）

### 3.3 执行顺序（重要）
**归档会锁死生成入口** → 正确顺序：
```
上传 → 解析 → 澄清 → FP分配模块 → 审核 → 确认 → 生成用例 → 归档 → KB验证
```

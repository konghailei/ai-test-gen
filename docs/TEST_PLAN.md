## §A 生成期间 API 可用性（v4.0.0 新增）

### A.1 背景
用例生成是分钟级长任务（SSE 流式，单批次 LLM 调用 60-220s）。本轮实测发现：**生成进行期间，其他 HTTP 端点响应严重劣化**——`/api/health` 无响应、`/auth/login` 20s 超时、任务 `cancel` 端点不通。

### A.2 验证方法
1. 启动 `POST /api/generate`（SSE）并保持连接
2. 生成期间每 30s 探测：`GET /api/health`（期望 200，<2s）
3. 生成期间探测 `POST /api/auth/login`（期望 200，<5s）
4. 生成期间尝试 `POST /requirements/tasks/{id}/cancel`（期望可达）
5. 断开 SSE 客户端，观察任务是否转 `interrupted` 且 API 恢复

### A.3 验收标准
| 项 | 标准 |
|---|------|
| health 延迟 | 生成期间 P95 < 2s |
| login 延迟 | 生成期间 P95 < 5s |
| cancel 可达性 | 生成期间可取消（或明确返回"不支持取消"），不得超时 |
| SSE 断开后 | 任务转终态（interrupted/failed），不长期占并发槽位 |

### A.4 实测基线（2026-10-15）
- ❌ health 无响应（curl 返回 000）
- ❌ login ReadTimeout（20s）
- ❌ cancel HTTP 000
- ✅ SSE 断开 → 任务转 `interrupted`，API 立即恢复 200
- **结论**：阻塞根因待定位（疑似 uvicorn 单事件循环被同步 LLM 调用占用）；断开 SSE 可作为"紧急逃生"手段，但 cancel 端点实际不可用属缺陷

## §C 澄清答案质量红线（v4.5 强化）

### C.1 新增禁令：禁止使用系统 `default_answer` 作为澄清答案
**实测（2026-10-15）**：系统为 `kb_llm_semantic_prd_upper_bound_rule_*` 类问题生成的 `default_answer` 是**伪答案**——内容是复述问题上下文（"该数量约束的处理规则是边界测试用例的必要依据…"），**不含任何具体数值或边界行为**。

用这类答案提交后的实测收敛曲线：
| 轮次 | 答案类型 | 剩余问题 |
|------|---------|---------|
| 第 1 轮 | `default_answer` + 泛化兜底 | 12 → 12（**零收敛**） |
| 第 2 轮 | DeepSeek 严谨答案（含数值+边界行为） | 12 → 4 |
| 第 3 轮 | DeepSeek 严谨答案 | 4 → 0 ✅ |

**结论**：v4.5 的"模型生成严谨答案"是**收敛的必要条件**，且**模型生成 ≠ 系统自带的 default_answer**。执行脚本时须显式调用外部模型（本次用 DeepSeek）生成答案，禁用系统建议答案。

### C.2 严谨答案的验收要素
每条答案必须包含：**具体数值 + 判定规则 + 超限/异常行为**。反例（不合格）："按文档执行"、"参考 PRD 描述"、"该约束是测试用例的必要依据"。

### G.1 流程与产出

| 步骤 | 结果 |
|------|------|

| FP 分配模块 + 审核 | ✅ 3/3 |

| 归档 + 向量化 | ✅ `archived` + `vectorization_status=completed` |
| **S5 漏项** | ❌ 文档 §3.3「敏感词校验」未提取为 FP |

### G.2 固定 KB 查询集结果

| # | 问题 | sources | 答案正确性 | 判定 |
|---|------|---------|-----------|------|
| 1 | 附件图片上传规则（关键值 jpg/5MB） | 8（Top1 相似度 0.746「图片附件上传」） | ✅ **精确含关键值**：jpg/jpeg/png/webp/gif、≤5MB、批量 9 张 | 通过 |
| 2 | 敏感词校验规则（分几级） | 8（Top 相似度仅 0.44，全是噪声：「需求澄清」「原型解析预算」） | ❌ `知识库中未找到相关内容` | **失败**（S6；根因 S5 漏项） |
| 3 | 工单超时自动挂起 | 8（同上，噪声） | ❌ `知识库中未找到相关内容` | **失败**（v1.0 文档确无工单模块 → 属预期未覆盖，但 sources 返回噪声仍不合理） |

**关键结论**：
1. KB 问答在**有强相关命中**时表现优秀（0.746 相似度、关键值齐全、按最新整理版采信）
2. 在**弱相关/未覆盖**时行为不自洽：既返回 8 条低分来源，又答"未找到"——前端会展示"参考来源"却无内容，误导用户
3. FP 提取完整性直接决定 KB 召回质量（S5 → S6 的因果链）

### G.3 执行顺序修正（重要）
**归档会锁死生成入口**：需求 `archived` 后调 `POST /api/generate` 返回 409「需求状态为 archived，仅 confirmed 可生成（archived 需求可用 resume 续跑）」。
正确顺序：**上传 → 澄清 → FP 审核 → confirm → 生成用例 → 归档 → KB 验证**。本轮首次执行因"先归档后生成"导致 0 条用例，已修正脚本。

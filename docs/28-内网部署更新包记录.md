### 1.2 配置变更清单（docker-compose.yml）

backend（api）service environment 新增（celery_worker **不加**——去重只在 API 进程编排链路）：

```yaml
    environment:
      # ...既有环境变量...
      - DEDUP_EMBED_WORKERS=auto        # 新增：auto = max(1, 物理核-1)；内存紧或想保守可留空/1
```

**配置语义**（`backend/app/config.py`）：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `DEDUP_EMBED_WORKERS` | `""`（串行） | `""`/`1`/`0`/`off` = 串行；`auto` = max(1, 物理核-1)；整数 N = N 个 ProcessPool worker。**内存预算：每 worker ~1.6GB**，开启前确认空闲内存 ≥ N×1.6GB |
| `DEDUP_EMBEDDING_MODEL_NAME` | `""` | A 路线专用模型，**默认关闭**（定标已否决，仅留代码入口）；重启 A 须先重跑定标 |
| `DEDUP_EMBEDDING_DEVICE` | `cpu` | 专用模型设备 |
| `DEDUP_SINGLE_CASE_SEC` | `4.0` | 进度消息预计时长系数（miss 数 × 系数） |
| `DEDUP_SEMANTIC_THRESHOLD` | `0.92` | 去重阈值（09-16 定标值，与 bge-large×整例JSON 深度绑定，**不要动**） |

### 1.3 部署路径：纯代码更新，零模型分发

模型是 compose bind mount（非镜像内置），本次**不加任何模型文件**，也不需要重建 base 镜像：

```bash
# 1. 更新代码（backend/ 目录）+ docker-compose.yml
# 2. 重建 backend 容器（代码挂载自动生效，无需 build 镜像）
docker compose up -d backend
```

⚠️ 若服务器内存充裕要开并行：先跑 §3 基准脚本确认加速比 ≥1.3×，再在 compose 加 `DEDUP_EMBED_WORKERS` 并 `up -d backend`。**不建议**为并行把模型打进基础镜像——那是 A 否决前的旧思路，本次无此必要。

## 3. 服务器部署后必做：分片并行基准

dev 机（8 逻辑核/16GB）已实测：线程池假并行（1.04×）、4 线程池负优化（0.38×）、ProcessPool 因内存不足无法完成基准——**dev 不开并行**。服务器多物理核 + 内存充裕时 ProcessPool 预期近线性，但必须实测：

```bash
docker exec ai-test-gen-api python /app/scripts/bench_dedup_embed.py
# 输出：各 workers 档位耗时 / 加速比 / 与串行的向量一致性校验 / 推荐配置
```

判定：加速比 ≥1.3× 的档位才值得开；否则 `DEDUP_EMBED_WORKERS` 留空（串行，此时收益主要来自预嵌入——它与核数无关，dev 机同样生效）。

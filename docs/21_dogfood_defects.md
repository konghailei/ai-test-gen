## 1. 总体结论

**验证目标全部达成。** 三版本文档（对应系统 v3.4.x / docs-17 / docs-18 三代能力）走完全部 11 步流程，
KB 累积曲线成立（命中率随版本递增），剔坏留好、SSE 收尸、CRSR 整理版等核心机制在真实数据下经受了实战验证。
自举过程中挖出 **4 个新缺陷**（均已修复或记录），并完成 2 项机制修复的端到端实证。

## 2. 三版本走查结果对比

| 维度 | v1.0 基线 | v2.0 原型HTML | v3.0 KB编译化 |
|---|---|---|---|
| 需求状态 | archived | archived | archived |
| FP 拆分 | 12 个（7模块全覆盖） | 2 个（粗粒度） | 4 个（知识库域） |
| 生成用例 | 124 条 | 31 条 | 70 条 |
| 入库分布 | 121 approved + 3 draft | 31 reviewed | **68 approved** + 2 draft |
| 坏条剔除 | 3（blocked_content） | 0 | 2（review_blockers） |
| 置信度均值 | 0.871 | 0.896 | 0.901 |
| 要点覆盖率 | — | 26.8%（97要点/2FP粗拆） | **79.2%**（101要点/4FP） |
| 澄清轮次 | 1 轮收敛 | 1 轮收敛（10问） | 2 轮收敛（10+7问） |
| 发布决策 | partial_block | human_review | **partial_block（剔坏留好实战）** |
| 生成耗时 | 9.5h（LLM窗口期） | 50min | 50min |

**质量观察**：
- 置信度随版本递增（0.871 → 0.896 → 0.901）：KB 越丰富，生成越有依据。
- v3.0 是**剔坏留好完整闭环首战**：decision=partial_block → 2 条坏条自动隔离进 error_cases（附剔除原因）→ 68 条好条正常分级入库 → 用户可见 awaiting_human_review 终态。
- v2.0 的 26.8% 覆盖率暴露 FP 粒度问题：2 个粗 FP 承载 97 个要点，分片生成覆盖不充分（见缺陷 D-3）。

## 5. 新发现缺陷（自举价值所在）

| # | 严重度 | 缺陷 | 状态 |
|---|---|---|---|
| D-1 | **严重** | SSE 断连导致流水线协程静默消失、任务永久 running 占互斥槽（except Exception 接不住 CancelledError + finally 内 await 再抛） | **已修复**（v3.5.3 shield 收尸）+ E2E 注入验证 + 2 次实战 |
| D-2 | 高 | persist_to_kb partial_block 分支残留旧变量名 `purged` → NameError → 回流中止（回归套件跑 happy path 未暴露） | **已修复**（purged_cases） |
| D-3 | 中 | auto_allowed 批次连坐：partial_block / quality_gate_forced 时全批降级 reviewed，高置信条（0.89）无法 approved，与方案B"照常分级"意图相悖 | **部分修复**（partial_block 已放开；**quality_gate_forced 场景仍连坐**，v2.0 的 31 条全 reviewed 即此因） |
| D-4 | 中 | archived 需求被彻底锁死无法 resume 续跑 | **已修复**（resume 语义放开） |
| D-5 | 低 | v2.0 FP 拆分过粗（2 FP/97 要点）导致覆盖率虚低 26.8%；同类 FP 粒度问题在 v1.0 未出现（12 FP），疑与文档结构相关，需积累更多样本 | 记录待观察 |

## 6. 遗留事项

1. **D-3 的 quality_gate_forced 连坐**：建议将 auto_allowed 条件从 `in ("auto_approve","partial_block")` 进一步放开——只要 case_level_reasons 为空（无内容级缺陷），高置信条即可自动入库。影响面小（仅状态分级），但需先定标"gate 强制放行时用户对自动入库的信任预期"。
2. **D-5 FP 粒度**：待 v3.0 类增量文档多积累几个样本后再判断是否需要提示词调优。
3. **git 提交**：本轮 5 个文件变更（generate.py / review_agent.py / task_guard 无变更 / publication_policy.py / dogfood 脚本）尚未提交，建议按"缺陷修复"与"dogfood 脚本"分两个 commit。
4. **docs/21 随验证数据持续更新**：后续每轮自举验证追加数据行。

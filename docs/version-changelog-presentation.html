阶段一 · 核心沉淀

功能点三级粒度

把"一个需求"拆成可独立审核、独立生成、可追溯的 FP 单元。related_fp 让每条用例都能回溯到功能点。

状态机门控

确认流程让质量可控：未确认(confirmed)的需求无法生成用例，杜绝"半成品进生产"。

FP 依赖图谱

依赖关系从"人肉记忆"变为可视化 + 影响分析可计算，为后续回归测试铺路。

双库架构

PG（结构化）+ Milvus（向量）双写，异步不阻塞，KB 不可用静默降级——稳定性防护的雏形。

设计决定

通道全部走 FULL（v1.6）：简单需求也需澄清 + 影响分析。这一短期"变慢"换来了长期的质量一致性，为后续强大澄清机制奠定基调。

阶段三 · 沉淀的澄清哲学

先 KB 后人工

所有语义问题（completeness/ambiguity）先查知识库，KB 有定义自动补全，KB 无才转人工——减少人机往返。

原因为本

问题基于原始文本分析产生（逻辑冲突/描述不清/信息缺失），不做"字段为空就提问"的机械补全。

不兜底

LLM 未返回精炼答案时不降低质量兜底，直接提示「需人工澄清」。

纠正确认

知识库纠正不直接写入，进入 pending_review 待审核，保证知识库纯净。

从"能检测"到"会思辨"

本阶段核心不是增加规则，而是让 LLM 自主理解文档语义（检测矛盾、引用、遗漏），规则层只做存在性兜底——这是澄清质量跃升的关键。

4. 第四阶段 v3.x — 收敛与体验跃升

v3.0.0 2026-08-12 · 提示词泛化
提示词全面泛化 + 影响分析双向 BFS + 同名 FP 合并
移除针对特定语料的死板模式，强化领域无关总原则；影响分析从单向改为双向 BFS（覆盖被依赖 + 依赖者）；功能点按名称合并去重。
v3.0.1 2026-08-14 · ⭐⭐ 里程碑
多轮澄清收敛重构（eval_answer_coverage）
从"提交答案后从零重新生成整轮问题"改为"评估上一轮答案是否覆盖"。覆盖→收敛；跳过→视为不关注；模糊→仅追问该问题；禁止发散。正常 1 轮正确回答即完全收敛。
v3.1.0 2026-08-17 · 当前
文档化发布
架构设计文档 + 前端使用手册整理，版本号统一同步。知识沉淀，让演进可追溯。

本期核心：多轮澄清收敛（v3.0.1）

澄清是"需求质量优先"的命脉。v3.0.1 彻底解决了问题发散与无法一轮收敛的痛点。

旧逻辑（发散）
  • 提交答案后从零做完整缺口检测
  • 已答问题被重复提问
  • 答案引出新话题 → 越问越多
新逻辑（eval_answer_coverage）
  • 只评估上一轮答案是否覆盖问题核心
  • 覆盖 → 收敛；跳过 → 不再追问
  • 模糊/不完整 → 仅对该问题追问 + 理由
  • 禁止发散，1 轮正确回答即收敛

5. 那些未采纳却推动演进的探索

每一次版本演进，都有被否决却有价值的方案。它们虽未进入最终版本，却塑造了系统的设计方向。

✗ MatchAgent — 从知识库检索历史用例辅助生成（v1.x → v2.0 移除）
最终未采纳

探索：用例生成阶段从 KB 检索历史用例注入。否决理由：v2.0 双 SRR 架构下，SRR 已足够详细，检索历史用例成本高且收益有限。替代方案：Few-shot 示例注入 Prompt + FP 定向生成上下文。推动价值：催生了"提示词注入上下文"这一更优的生成范式。

✗ 向量库 ChromaDB → pgvector → Milvus（三阶段迁移规划）
最终采用 Milvus

探索：三阶段演进论证（纯向量库 / PG 扩展 / 专用向量库）。取舍：最终统一采用 Milvus（规模、性能、生态最优），前两阶段仅作为规划论证。推动价值：决定了向量存储抽象层设计，让替换成本降为配置级。

✗ legacy_data_impact 字段由 LLM 推断预填充（曾采用 → v2.8.60 修正）
最终修正为留空

探索：LLM 基于功能点描述推断历史数据影响字段。否决理由：原文未提及不应臆造，应由澄清环节补充（"原文未提及则留空"原则）。推动价值：确立"不臆造、由澄清补齐"的强约束。

未采纳的探索（续）

✗ 字段补全式澄清提问（曾采用 → v2.8.60 移除）
最终移除

探索：字段为空就自动生成"XX是什么/如何迁移"补全式提问。否决理由：某些字段允许为空（如 legacy_data_impact），机械提问不靠谱。替代：保留固定优化提问（是否影响历史数据 + 影响范围），由用户主动补充；问题一律基于原文分析产生。推动价值：明确"问题必须锚定原始文本，不做机械补全"的标准。

✗ 应用层 go_live_date 覆盖排序（曾采用 → v2.8.55 改为 RRF 时间衰减）
最终被替代

探索：应用层直接用 go_live_date 覆盖相似度排序。否决理由：破坏相关性排序，旧版本可能反超。替代：RRF 时间衰减因子融入融合分数。推动价值：确立"相关性优先、时效加权"的检索融合原则。

✗ 敏感词编造通用选项（曾出现 → 收紧模板触发）
最终收紧

探索：问题模板硬编码"网络异常/并发冲突"等通用场景。否决理由：脱离原文档的臆造选项。替代：选项留空、仅当 LLM 精炼成功才填充。推动价值：杜绝"文档未描述却编造规则"，坚持基于上下文的生成。

共同主线

所有被否决的方案都指向同一原则——忠于原始需求，不臆造；能由澄清/KB 补齐的，不靠机械推理。

"留"与"弃"的智慧

被验证沿用
  • 双 SRR 分层（v2.0）
  • DLQ + 四层防护（v2.2）
  • 澄清先 KB 后人工（v2.8.x）
  • RRF 时间衰减（v2.8.55）
  • 多轮收敛 eval_answer_coverage（v3.0.1）
经研判放弃
  • MatchAgent 历史用例检索（→ Few-shot）
  • ChromaDB / pgvector（→ 统一 Milvus）
  • 字段补全式提问（→ 基于原文分析）
  • 应用层版本覆盖排序（→ RRF 衰减）
  • LLM 预填充 legacy_data_impact（→ 澄清补齐）
演进不是加法

真正成熟的系统不是"功能越堆越多"，而是每一步都经过"取舍"。被否决的方案证明了团队敢于纠错、忠于需求的判断力——这本身就是最有价值的沉淀。

系统核心价值

自动化提效

需求文档直达测试用例，减少手工编写 60%+，支持功能/边界/异常/安全/性能多维用例。

回归智能化

影响分析（双向 BFS）+ 依赖图谱，自动识别优化影响范围，推荐精准回归测试。

质量质量闸门

确认流程 + 质量门禁 + 多轮澄清收敛，确保进入生成的每个需求都明确、无遗漏、无矛盾。

知识沉淀

审核后的用例和历史需求回写知识库，版本时效 + 时间衰减 + 纠正审核，越用越准。

一句话

AI-Test-Gen 不是"一次性的生成工具"，而是一套越用越聪明的需求测试闭环系统。

# 项目管理系统 - 历史版本管理模块 优化需求 v1.1

> 版本：v1.1 | 基于 v1.0 优化 | 模块：版本管理 | 对应测试阶段：阶段2/3 项目2

## 1. 简介

基于 v1.0 的优化版本改造，重点是调整版本保留策略，使重要历史版本可以更灵活地保留。

## 2. 用户故事

- 作为 项目经理，我希望 手动标记版本不再受限 50 个上限，以便 重要历史版本都可以保留。
- 作为 团队成员，我希望 上传图片时能沿用现有规则，以便 保持一致的上传体验。

## 3. 功能描述

### 3.1 图片上传功能

沿用现有图片上传规则（保持不变，本次不改动）。

> **说明**：此处故意写得模糊，触发 ref_undef 检测。实际应从 v1.0 KB 中命中：格式 jpg/jpeg/png/webp/gif、单文件 ≤5MB、超限提示文案、批量 9 张、缩略图 200x200、文件名规范。

### 3.2 版本数量策略调整

手动标记版本：不再限制 50 个上限（取消自动淘汰机制）；重要历史版本永久保留。

> **矛盾点**：v1.0 规定"手动标记版本最多保留 50 个，超过后最旧的手动标记版本自动降级为普通版本"，本版本改为"不再限制 50 个上限"。应触发矛盾检测。

自动保存版本：沿用现有自动保存保留策略。

> **模糊引用**：应从 v1.0 KB 命中"自动保存版本（草稿）最多保留 20 个"。

小修订判定：沿用现有小修订相关规则。

> **模糊引用**：应从 v1.0 KB 命中"小修订判定标准：正文改动 < 5%"。

### 3.3 敏感词校验

上传的图片素材的文件名、描述字段：沿用现有敏感词校验规则，保持现有素材上传策略一致。

> **模糊引用**：应从 v1.0 KB 命中"敏感词库分为三级：一级（政治敏感）、二级（商业敏感）、三级（一般敏感）"以及命中处理逻辑。

## 4. 权限

权限控制沿用现有历史版本模块的权限控制规则。

> **模糊引用**：应从 v1.0 KB 命中"项目经理：可创建/归档版本、可上传图片、可审核敏感内容"等权限定义。

## 5. 验收标准

**AC-01**：手动标记版本列表支持任意数量标记成功。
**AC-02**：标记 51/60/100 个版本都不会被自动淘汰。
**AC-03**：版本数量无上限，旧版本不再自动淘汰（51/60/100 个均保留）。
**AC-04**：沿用的图片上传规则、权限控制规则、敏感词校验规则均与现网一致。

## 6. 优化影响范围

本次优化涉及以下历史数据迁移：

- 已被自动淘汰的旧手动标记版本：需要恢复其标记状态
- 草稿版本超过 20 个的项目：不影响（草稿策略未变）

> **优化影响配套问题**：应生成 kb_optimization_impact + kb_optimization_impact_scope 两条配套问题。

# 项目管理系统 - 历史版本管理模块 优化需求 v1.2

> 版本：v1.2 | 基于 v1.1 优化 | 模块：版本管理 | 对应测试阶段：阶段2/3 项目3

## 1. 简介

本版本调整敏感词校验策略，从"三级分类"简化为"两级分类"，降低审核成本。同时引用 v1.0 的图片上传规则。

## 2. 用户故事

- 作为 系统管理员，我希望 敏感词分类简化为两级，以便 降低审核成本。
- 作为 团队成员，我希望 上传图片时能沿用现有规则，以便 保持一致的上传体验。

## 3. 功能描述

### 3.1 图片上传功能

沿用现有图片上传规则（保持不变，本次不改动）。

> **模糊引用**：应从 v1.0 KB 命中图片上传规则全集：格式 jpg/jpeg/png/webp/gif、单文件 ≤5MB、超限提示文案、批量 9 张、缩略图 200x200、文件名规范。

### 3.2 敏感词校验策略调整

敏感词库从三级分类调整为两级分类：

- 一级敏感词（严重违规）：拒绝上传，返回"内容违规，请修改后重试"
- 二级敏感词（一般违规）：允许上传但标记为"待审核"，需项目经理审核通过后才对外可见

> **矛盾点**：v1.0 规定"敏感词库分为三级"，本版本改为"两级分类"。应触发矛盾检测。

> **删除项**：v1.0 中的"三级敏感词：允许上传但记录日志，不阻断流程"被删除。

敏感词库更新频率：沿用现有更新策略。

> **模糊引用**：应从 v1.0 KB 命中"敏感词库更新频率：每月一次，由系统管理员维护"。

### 3.3 版本保留策略

沿用 v1.1 的版本保留策略调整：手动标记版本不再限制 50 个上限；自动保存版本沿用现有保留策略；小修订判定沿用现有规则。

## 4. 权限

权限控制沿用现有历史版本模块的权限控制规则。

> **模糊引用**：应从 v1.0 KB 命中权限定义（项目经理/团队成员/访客角色的权限矩阵）。

## 5. 验收标准

**AC-01**：上传文件名含一级敏感词的图片，返回"内容违规，请修改后重试"。
**AC-02**：上传文件名含二级敏感词的图片，标记为"待审核"，需项目经理审核通过后才对外可见。
**AC-03**：敏感词库更新后，新上传的图片素材立即应用新规则。
**AC-04**：沿用的图片上传规则、权限控制规则均与现网一致。

## 6. 优化影响范围

本次优化涉及以下历史数据迁移：

- 已按三级分类标记的待审核素材：需按两级分类重新审核
- 已按三级分类记录日志的素材：日志保留，不影响

> **优化影响配套问题**：应生成 kb_optimization_impact + kb_optimization_impact_scope 两条配套问题。

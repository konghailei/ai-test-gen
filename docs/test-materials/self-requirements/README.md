# 本系统需求文档（自证测试载体，self-requirements）

> 本目录存放 **AI-Test-Gen 平台自身**的需求文档，专用于**自证测试（self-dogfood）**：
> 把系统自己的需求喂给系统 → 走完整 11 步流程生成测试用例 → 再用生成的用例反过来验证系统自身。
>
> ⚠️ 与 `docs/test-materials/test-requirements/`（历史版本管理模块）、`docs/test-materials/dogfood-requirements/`（DevBlog 等）区分：
> 本目录是**本系统自身**的需求，其他目录是**被测业务**的需求。

## 文档与轮次映射

| 文件 | 轮次 | 主题 | 覆盖重点 | 验证目标 |
|------|------|------|---------|---------|
| `v1.0_core_baseline.md` | 第一轮 | 核心全流程基线 | 上传/解析/澄清/确认/生成/审核/影响分析/知识库/问答/纠正/系统管理 | 基线入库 + 首轮用例生成 + KB 固定查询 |
| `v2.0_enhancement.md` | 第二轮 | 协作与治理增强 | 多人协作/版本管理/质量治理/多模态/知识库编译化/评审报告 | **KB 累积**（引用第一轮规则应命中）+ 冲突检测 |
| `v3.0_governance.md` | 第三轮 | 稳定性与边界治理 | 长任务稳定性/并发治理/向量一致性/错误降级/检索边界/前端交互 | 细粒度功能点覆盖 + 降级路径留痕 |

## 三轮拆分原则

- **第一轮 = 核心链路全貌**：保证系统能被完整"跑通"，产出基线知识。
- **第二轮 = 增强能力 + 累积验证**：在第一轮之上叠加，重点验证 KB 越用越好用。
- **第三轮 = 小功能点集中补充**：稳定性/可观测/边界这类描述密度低、易被生成器遗漏的点。

三轮文档**渐进累积**：第三轮需求中会引用第一/二轮的规则（如"语义去重阈值""相关度门槛"），用于验证跨版本 KB 检索。

## 第四轮：用例可执行性验证（计划）

前三轮走"上传 → 生成用例"链路。**第四轮不再是上传需求，而是用前三轮生成好的测试用例，去实际执行验证系统**。

### 第四轮验证目标

| 验证维度 | 方法 | 期望 |
|---------|------|------|
| **用例可执行性** | 抽取前三轮生成的高优先级用例，用 API/Playwright 实跑 | 统计可执行率；识别"臆造接口/无触发路径/破坏性操作"类不可执行用例 |
| **多用户并发上传** | 3 用户并发上传不同需求 | 无报错/超时/死锁，响应时间可接受 |
| **需求分析正确性** | 对比生成用例的步骤与系统真实行为 | 步骤指向的端点/UI 真实存在 |
| **依赖图谱正确性** | 用生成的用例验证影响分析 | 图谱覆盖变更相关功能点 |
| **知识问答正确性** | 用生成的用例提问，核对来源与答案 | 命中归档内容，关键值齐全 |
| **知识库纠正** | 提交纠正 → 审核 → 回写，验证生效 | 纠正正确被系统接受并回写 |
| **生成的用例覆盖度** | 对照三轮需求功能点清单 | 关键功能点均有对应用例 |

### 第四轮执行顺序

```
前三轮：上传 v1.0/v2.0/v3.0 → 澄清 → 确认 → 生成用例 → 归档
   ↓
第四轮：
  1. 汇总前三轮生成的全部用例（按需求/类型/优先级分组）
  2. 抽取可执行子集（排除破坏性操作类）
  3. 逐条实跑：API 用例用脚本直调，UI 用例用 Playwright
  4. 记录：通过 / 失败（系统缺陷）/ 不可执行（用例缺陷）
  5. 双向归因：
     - 用例不可执行 → 记录到"生成器可执行性"问题（U2/U3/U6 类）
     - 用例可执行但系统实际行为不符预期 → 记录为系统缺陷
  6. 输出第四轮验证报告
```

## 产物

- 前三轮：每轮 `_e2e_tmp/self_<version>.json`（步骤结果 + 澄清收敛 + 用例统计 + KB 命中）
- 第四轮：`_e2e_tmp/self_exec_report.json`（用例执行结果矩阵）+ `SELF_TEST_REPORT.md`

## 使用说明

1. **上传顺序**：严格 v1.0 → v2.0 → v3.0，确保 KB 累积正确。
2. **同产品多项目**：三轮可归属同一产品（产品名如 `AI-Test-Gen 自证`），通过项目版本号区分。
3. **澄清纪律**：澄清回答须由模型生成严谨答案（含具体数值+判定规则+边界行为），禁用系统 `default_answer` 与脚本兜底。
4. **归档前置**：每轮走完"上传→澄清→FP 分配模块→审核→确认→生成用例→归档"全流程。
5. **产物保留**：所有测试数据保留，便于第四轮复跑与对比。

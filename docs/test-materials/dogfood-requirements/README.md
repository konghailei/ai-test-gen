
## 上传顺序与产品规划

1. 系统内新建产品「AI-Test-Gen 自举验证」，划分 7 个模块：
   ① 需求管理 ② 需求分析 ③ 用例生成 ④ 知识库 ⑤ 影响分析 ⑥ 原型解析 ⑦ 系统管理
2. 严格按 v1.0 → v2.0 → v3.0 顺序上传（每版本一个项目），确保 KB 累积正确。
3. 每版本走完 11 步流程：建项目 → 上传 → 解析轮询 → 澄清（按系统设计实情回答，目标一轮收敛）→ FP 分配模块 → FP 全量审核 → 确认 → SSE 生成 → 项目归档 → KB 验证。

## 验证要点

- **FP 拆分正确性**：v1.0 应拆出与 7 模块功能对应的功能点（不含系统没有的功能——幻觉检测点）。
- **数值规则保真**：SRR 与用例中的具体数值（3 轮/5 问/0.70/400 节点/10MB/60 RPM/240 秒）与本文档一致，不被 LLM 改写。
- **KB 累积曲线**：v1.0 归档后 Q1-Q3 命中；v2.0 后 Q4 命中且 Q3 答案更新（含 html）；v3.0 后 Q5/Q6 命中——命中率随版本递增。
- **版本变更覆盖**：v3.0 引入的"优先采信整理版"与 v1.0 §3.9.4 的"时间靠后为准"是兜底关系，问答须体现层级。
- **澄清收敛**：澄清问题按系统实情严谨回答后应一轮收敛（无 critical/important 追问）；3 轮强制放行视为文档结构性缺失信号，须回补文档。

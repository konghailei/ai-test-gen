 1. 引言                                                                                                                                                                         +
 1.1 目的                                                                                                                                                                        +
 本文档定义“团队协作白板”产品的核心功能、非功能需求与交付计划，为研发、测试、设计团队提供统一依据，确保 MVP 在 Q2 内高质量上线。                                                 +
 1.2 范围                                                                                                                                                                        +
 产品面向产品经理、设计师、远程研发团队的协作场景，支持在线白板绘制、实时多人协作、评论批注、权限管理与历史回溯。本期 MVP 覆盖 Web 端与桌面端（Electron），移动端仅支持只读查看。+
 1.3 术语定义                                                                                                                                                                    +
 | 术语 | 说明 |                                                                                                                                                                 +
 |---|---|                                                                                                                                                                       +
 | CRDT | Conflict-free Replicated Data Type，无冲突复制数据类型，用于多客户端实时同步 |                                                                                         +
 | Op | Operation，用户对画布元素的单次原子操作（如新增、移动、删除） |                                                                                                          +
 | Room | 协作房间，一组同时编辑同一白板的用户会话集合 |                                                                                                                         +
 | Optimistic UI | 乐观更新：本地先渲染用户操作，再等待服务端确认 |                                                                                                              +
 | 快照 | 画布某一时刻的完整状态导出，用于历史版本与快速恢复 |                                                                                                                   +
 2. 总体描述                                                                                                                                                                     +
 2.1 产品愿景                                                                                                                                                                    +
 打造一款低门槛、高性能的团队协作白板，让分布式团队能够像面对面一样进行头脑风暴、流程梳理与原型设计，成为 B2B 协作套件的核心入口。                                               +
 2.2 用户角色                                                                                                                                                                    +
 | 角色 | 描述 | 核心权限 |                                                                                                                                                      +
 |---|---|---|                                                                                                                                                                   +
 | 团队管理员 | 创建并管理团队、设置计费与集成 | 全部权限，可分配所有者 |                                                                                                        +
 | 白板所有者 | 创建白板并邀请成员 | 编辑、分享、删除、导出 |                                                                                                                    +
 | 编辑者 | 参与实时协作与评论 | 增删改元素、评论 |                                                                                                                              +
 | 评论者 | 查看白板并发表评论 | 只读 + 评论 |                                                                                                                                   +
 | 访客 | 通过公开链接临时访问 | 只读（可配置为评论） |                                                                                                                          +
 2.3 系统架构                                                                                                                                                                    +
 系统采用分层架构，前端基于 React + Canvas 实现高性能渲染，后端通过 WebSocket 协作网关承载实时同步，核心依赖 CRDT 引擎解决并发冲突，持久化层采用 PostgreSQL + 对象存储。         +

                                                                                                                                                                                 +
 【图片类型】架构图                                                                                                                                                              +
 【主要内容】该图片展示了一个支持实时协作的应用系统（如在线白板或文档编辑器）的分层系统架构，涵盖了从用户界面到数据存储的完整技术栈。                                            +
                                                                                                                                                                                 +
 【节点/组件清单】                                                                                                                                                               +
 - **表示层 / Presentation**                                                                                                                                                     +
     - Web 浏览器 (React + Canvas)：基于Web技术的用户界面，使用React框架和Canvas绘图。                                                                                           +
     - 桌面客户端 (Electron)：基于Electron框架的桌面应用程序。                                                                                                                   +
 - **接入层 / Gateway**                                                                                                                                                          +
     - CDN 静态资源分发：负责分发静态资源，加速加载。                                                                                                                            +
     - 负载均衡 Nginx：负责流量分发和负载均衡。                                                                                                                                  +
 - **应用服务层 / Application**                                                                                                                                                  +
     - 鉴权服务 (OAuth2/JWT)：处理用户身份验证和授权。                                                                                                                           +
     - REST API 服务：提供标准的HTTP接口服务。                                                                                                                                   +
     - 协作网关 (WebSocket)：处理实时双向通信连接。                                                                                                                              +
 - **核心引擎层 / Engine**                                                                                                                                                       +
     - CRDT 同步引擎 (Yjs / Automerge)：核心协作算法引擎，用于解决多用户并发编辑冲突。                                                                                           +
     - 实时消息总线：负责系统内部的消息传递和路由。                                                                                                                              +
 - **数据 & 基础设施 / Data**                                                                                                                                                    +
     - PostgreSQL 元数据/权限：关系型数据库，存储用户信息、文档元数据和权限配置。                                                                                                +
     - Redis 在线状态/锁：缓存数据库，存储用户在线状态和分布式锁。                                                                                                               +
     - 对象存储 画布快照/图片：存储大文件，如画布的历史快照和上传的图片。                                                                                                        +
                                                                                                                                                                                 +
 【关系与流向】                                                                                                                                                                  +
 - **整体流向**：                                                                                                                                                                +
     - 左侧箭头（用户请求）：表示用户请求从表示层向下经过接入层、应用服务层、核心引擎层，最终到达数据层。                                                                        +
     - 右侧箭头（状态/数据）：表示数据和状态从数据层向上经过各层，最终返回给表示层展示。                                                                                         +
 - **层级依赖**：                                                                                                                                                                +
     - 表示层依赖接入层进行资源获取和请求转发。                                                                                                                                  +
     - 接入层将请求路由至应用服务层。                                                                                                                                            +
     - 应用服务层调用核心引擎层处理业务逻辑和同步。                                                                                                                              +
     - 核心引擎层依赖数据层进行持久化存储和状态读取。                                                                                                                            +
                                                                                                                                                                                 +
 【关键信息】                                                                                                                                                                    +
 - **技术栈特征**：系统明确使用了 **CRDT (Conflict-free Replicated Data Types)** 算法（具体提及 Yjs / Automerge），表明这是一个强依赖实时协作同步的系统。                        +
 - **通信协议**：同时使用了 **REST API**（常规请求）和 **WebSocket**（实时协作），体现了混合通信模式。                                                                           +
 - **前端技术**：Web端使用 **React + Canvas**，桌面端使用 **Electron**，说明系统跨平台且注重图形渲染能力。                                                                       +
 - **数据存储策略**：采用了混合存储策略，PostgreSQL存结构化数据，Redis存高频状态，对象存储存非结构化大文件。                                                                     +

 3.2 实时协作                                                                                                                                                                    +
 多人同时编辑同一白板时，系统需保证操作低延迟、无冲突、可恢复。关键流程如下：                                                                                                    +
 【图片2内容描述（多模态识别）】                                                                                                                                                 +
                                                                                                                                                                                 +
                                                                                                                                                                                 +
 【图片类型】流程图                                                                                                                                                              +
 【主要内容】描述了实时协作编辑系统中，从用户本地操作到服务端持久化存储的完整数据流转与同步流程。                                                                                +
                                                                                                                                                                                 +
 【节点/组件清单】                                                                                                                                                               +
 - 节点1：1. 用户操作画布 (绘制 / 移动 / 编辑) — 用户在前端进行具体的绘图或编辑动作。                                                                                            +
 - 节点2：2. 生成本地变更操作 Op — 系统将用户动作转化为操作对象（Operation）。                                                                                                   +
 - 节点3：3. 乐观更新本地视图 — 在等待服务器确认前，先在本地界面展示变更结果。                                                                                                   +
 - 节点4：4. 经 WebSocket 发送至协作网关 — 通过网络协议将操作数据发送给服务器。                                                                                                  +
 - 节点5：5. 服务端 CRDT 合并 — 服务器使用 CRDT 算法处理并发操作。                                                                                                               +
 - 节点6：6. 广播至房间内其他客户端 — 将合并后的操作发送给同一房间的其他用户。                                                                                                   +
 - 节点7：7. 其他客户端应用并渲染 Op — 接收方客户端执行操作并更新界面。                                                                                                          +
 - 节点8：8. 服务端持久化至存储 — 将最终数据保存到数据库或文件存储中。                                                                                                           +
                                                                                                                                                                                 +
 【关系与流向】                                                                                                                                                                  +
 - 节点1 → 节点2：用户操作触发本地操作对象的生成。                                                                                                                               +
 - 节点2 → 节点3：生成的操作对象用于更新本地视图。                                                                                                                               +
 - 节点3 → 节点4：本地更新完成后，操作数据通过网络发送。                                                                                                                         +
 - 节点4 → 节点5：网关接收数据后，交由服务端进行 CRDT 合并处理。                                                                                                                 +
 - 节点5 → 节点6：合并完成后，数据被广播给其他客户端。                                                                                                                           +
 - 节点6 → 节点7：其他客户端接收数据并进行渲染。                                                                                                                                 +
 - 节点7 → 节点8：流程最终指向服务端的数据持久化存储。                                                                                                                           +
                                                                                                                                                                                 +
 【关键信息】                                                                                                                                                                    +
 - **技术特性标注（右侧）**：                                                                                                                                                    +
     - 节点1对应：本地交互                                                                                                                                                       +
     - 节点2对应：diff / patch                                                                                                                                                   +
     - 节点3对应：Optimistic UI                                                                                                                                                  +
     - 节点4对应：低延迟传输                                                                                                                                                     +
     - 节点5对应：无冲突阻塞                                                                                                                                                     +
     - 节点6对应：fan-out                                                                                                                                                        +
     - 节点7对应：实时同步                                                                                                                                                       +
     - 节点8对应：快照 + 增量                                                                                                                                                    +
 - **冲突处理机制**：在节点5（服务端 CRDT 合并）与节点6（广播）之间标注有“冲突由 CRDT 自动合并 无需人工介入”，说明系统具备自动解决并发冲突的能力。                               +
 - **颜色编码**：                                                                                                                                                                +
     - 蓝色节点：客户端侧的操作与更新（节点1, 2, 3, 7）。                                                                                                                        +
     - 橙色节点：网络传输与广播环节（节点4, 6）。                                                                                                                                +
     - 紫色节点：服务端核心逻辑处理（节点5）。                                                                                                                                   +
     - 灰色节点：最终存储环节（节点8）。                                                                                                                                         +

系统架构总览

LangGraph DAG 流水线 + 存储分层

流水线
需求分析到用例生成的端到端链路（由 LangGraph 编排）：上传 → 解析 → 澄清（含知识库基线补全）→ 质量门禁 → 影响分析 → 生成 → 审核
通道选择
select_channel 按需求复杂度分流：FULL 走澄清闭环，FAST 直接进质量门禁
质量门禁
gate 评估完整性；未通过且可重试则回到 clarify，达到上限强制通过
存储分层
PostgreSQL（关系型）+ Milvus（向量数据库）+ MinIO（对象存储）+ etcd（元数据服务）
1
DAG 编排
LangGraph 的 StateGraph 把节点编译为可执行 DAG。固定节点依次为：parse → select_channel → clarify → gate → impact → generate → review。select_channel 按条件分支（FULL / FAST），gate 按条件分支（通过进 impact / 未通过回 clarify 重试）。
2
双写落库
解析阶段生成的 SRR 同时写入 PostgreSQL（结构化存储）和 Milvus（向量化存储），确保关系查询和语义检索都能命中。

需求分析流程

上传 → 解析 → 澄清 → 门禁 → 归档

1
上传需求
支持 .md / .docx / .txt 格式，系统自动提取文本和图片内容
2
需求解析
ReqAgent 将原始文本转化为结构化需求规格（SRR），包含功能概述、前置条件、业务规则等
3
需求澄清
ClarifyAgent 自动检测歧义和遗漏，结合知识库进行基线补全，生成澄清问题供人工确认
4
质量门禁
QualityGate 评估完整性分数，未通过则回到澄清步骤（最多3轮），通过后归档入库

知识库架构

三层存储 + 增量基线补全

向量检索
基于 Milvus 的语义相似度检索，支持跨需求复用历史基线数据
基线补全
增量需求上传时，自动从知识库检索相似需求的 SRR 字段进行补全
冷启动
首个需求无历史基线，系统进入冷启动模式，后续需求逐步积累知识库

测试用例生成

SRR → UTCF → 多格式导出

1
影响分析
ImpactAnalysisAgent 分析需求变更对现有测试用例的影响范围
2
用例生成
GenAgent 基于 SRR 和知识库上下文，生成结构化测试用例（UTCF格式）
3
用例审核
ReviewAgent 对生成的用例进行质量审核，检查覆盖率和规范性
4
导出
支持 XMind、Markdown、PyTest、Gherkin 多种格式导出

功能模块说明

系统核心功能模块一览

项目管理
管理产品下的项目和版本，支持增删改查
模块管理
管理功能模块划分，支持模块间依赖关系配置
依赖图谱
可视化展示功能模块间的依赖关系
任务管理
查看需求分析任务状态、进度和耗时
知识问答
基于知识库的智能问答，快速检索需求细节
管理后台
产品、用户、角色、提示词、日志、系统设置管理

术语表

系统核心概念与缩写说明

SRR（Software Requirement Specification）
结构化需求规格，包含功能概述、前置条件、业务规则、验收标准等字段
UTCF（Universal Test Case Format）
通用测试用例格式，系统生成的标准用例数据结构
KB（Knowledge Base）
知识库，基于 Milvus 向量数据库构建的语义检索系统
DAG（Directed Acyclic Graph）
有向无环图，LangGraph 用于编排需求分析流水线的数据结构
QualityGate
质量门禁，评估需求分析完整性的检查点，分数低于阈值需重新澄清
ClarifyAgent
需求澄清代理，自动检测需求歧义并结合知识库进行基线补全
